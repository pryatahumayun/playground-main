# Cloud Architecture Playground

This repository is a curated public slice of a much larger private learning and project space. It brings together the areas I spend the most time growing in: cloud architecture, software engineering, AI, infrastructure, systems design, and technical documentation.

What makes this repo meaningful to me is that it is not just a collection of notes and not just a collection of code. It is a working record of how I learn, how I think through architecture, and how I turn concepts into something concrete. Some of what is here comes from hands-on implementation. Some comes from production-adjacent work, design participation, operational observation, architecture review, and studying existing systems deeply enough to support real changes safely.

This is also not meant to represent everything I have worked on. It is a snapshot: the projects, patterns, notes, and reference material I felt were worth organizing and sharing because they show how I approach modern engineering problems across cloud platforms and system boundaries.

## What This Repository Includes

- cloud projects and deployment experiments
- Azure and AWS service notes
- infrastructure as code examples using Bicep, Terraform, and Terragrunt
- Kubernetes, container, networking, and platform documentation
- AI and RAG study material
- architecture principles, systems engineering, and system design study guides
- project-specific documentation with screenshots, deployment flows, and lessons learned

## How To Read This Repo

You do not need to read it front to back. Each folder is meant to stand on its own.

If you are here for hands-on work, start in `projects/`.

If you are here for platform or cloud study notes, start in `azure/`, `aws/`, `kubernetes/`, or `ai/`.

If you are here for interview preparation or architecture thinking, start in `architecture-concepts/`, `systems-engineering/`, or `enterprise-architecture/`.

## What I Wanted This Repo To Be

I wanted this repository to feel practical, not performative.

That means:

- documenting concepts in language I can actually use and remember
- connecting theory to real implementation choices
- capturing tradeoffs, not just ideal answers
- showing the architecture around systems, not just the application code
- making room for both study material and real build work

## A Note On Scope

This repository is still only a snapshot of my broader learning and experience. It is intentionally selective. I share the parts that best reflect what I have been building, studying, refining, and documenting over time.

See each folder's `README.md` for deeper detail.***
