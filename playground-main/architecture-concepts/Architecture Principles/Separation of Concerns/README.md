# Separation of Concerns

Separation of concerns means splitting a system so each part focuses on a distinct responsibility.

## What To Know

- UI, business logic, data access, and infrastructure concerns should not blur together
- separation improves clarity and change isolation
- boundaries can exist in code, services, or platforms

## Good Interview Points

- clean layering reduces accidental complexity
- architecture patterns like MVC or hexagonal architecture support separation
- too many layers can become ceremony if the system is simple
